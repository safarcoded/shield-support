# S.H.I.E.L.D. — Student Help Initiative for Equity, Listening and Dignity

A responsive, static multi-page website prototype for the proposed S.H.I.E.L.D. student-support initiative.

## Contents

- `index.html` — Homepage
- `about.html` — Mission, vision, and founding motivation
- `get-support.html` — Pilot scope and support information
- `how-it-works.html` — Proposed case-review process
- `transparency.html` — Accountability and future reporting
- `privacy.html` — Privacy principles
- `applicant-rights.html` — Proposed applicant rights
- `complaints.html` — Complaints and corrections
- `faq.html` — Frequently asked questions
- `contact.html` — Demonstration interest form
- `pilot.html` — Current pilot status and launch dependencies
- `policies.html` — Policy directory
- `404.html` — Not-found page
- `style.css` — Shared responsive design system
- `app.js` — Mobile navigation, current-page state, and demonstration-form behavior

## Run locally

Open `index.html` in a browser, or use a local static server.

## GitHub Pages deployment

1. Extract this ZIP.
2. Upload the files and folders' contents to the repository root (or a dedicated folder configured for Pages).
3. Replace the old `index.html` and avoid leaving conflicting old application entry points at the root.
4. In repository Settings → Pages, select the appropriate branch and root folder.
5. Wait for deployment and test all page links on the published site.

## Important launch boundaries

This is a **static informational prototype**, not a live support service.

- The pilot is marked as in preparation.
- No real case intake or secure case storage is implemented.
- The contact form is deliberately a demonstration; it does not transmit or store form data.
- Do not collect sensitive information until a suitable secure intake system, access controls, retention/deletion rules, privacy notice, and safeguarding process are ready.
- No payment, donation, or financial-assistance mechanism is included.
- Do not add fabricated case statistics, endorsements, or claims of registration.
- Final policies and any fundraising must receive appropriate review and adult oversight before launch.

## Design principles

Warm teal and blue palette, accessible typography, responsive layout, keyboard focus states, reduced-motion support, plain-language content, and consistent navigation.
